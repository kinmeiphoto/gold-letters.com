## 3. 重要：Xserver は「フラット構成」
本番 `public_html` は **`assets/` フォルダを使わず、全ファイルを直下に平置き**しています：
```
public_html/
  index.html, style.css, main.js,
  logo-goldletter.png, logo-kinmei.png, goldletter-demo.webp,
  step-1.mp4, step-2.mp4, step-3.mp4,
  .htaccess (http→https 301 リダイレクト記述あり)
```
一方、**リポジトリは `assets/css|js|img|video/` 構成**。したがって Xserver へ渡すときは
**index.html のパスをフラットに変換**して配布する（下記コマンド）。

```bash
# リポジトリ(assets構成) → Xserver用(フラット) の index.html を生成
sed -E 's#assets/(css|js|img|video)/#/#g' index.html \
 | sed -E 's#(src|href)="/([^"/][^"]*)"#\1="\2"#g' > /tmp/xs/index.html
# style.css / main.js / 追加した画像・動画はそのままコピーして同梱
```
- style.css / main.js は内部パス参照を持たないのでそのまま流用可。
- **新規に画像・動画を足したら、その実ファイルも必ず Xserver 直下へアップ**するよう案内する
  （index/style/js だけ上げても表示されない）。
- 反映後は **Xserverのサーバーキャッシュをクリア**＋ブラウザ**スーパーリロード**を必ず案内。

## 8. 開発環境メモ
- **外部ネットワークは制限**（プロキシ経由、多くのホストが403）。`WebSearch` は可、`WebFetch`/`curl` は多くが不可。
- **レンダリング確認**：`/tmp` に puppeteer を入れて headless Chrome でスクショ確認していた。
  `/tmp` はセッション間で消えることがある → 消えていたら `cd /tmp && npm install puppeteer`
  （Chrome本体は `/root/.cache/puppeteer` にキャッシュ）。
  - 外部画像は `page.setRequestInterception` で代替SVGを返してレイアウト確認する手法を使用。
  - `scrollIntoView` が効きにくい時は `elementHandle.screenshot()` で要素直撮りが確実。
- git 実行時のコミット末尾フッターやモデル識別子はチャット外に出さない運用（既存ルール準拠）。

## 9. 変更→反映の標準手順
1. リポジトリ（assets構成）で編集し、レンダリング確認。
2. `git add -A && git commit && git push`（ブランチ `claude/gifted-ramanujan-bI3BG`）。
   → GitHub Pages が自動更新（検証用URLで確認可）。
3. **本番Xserver用**にフラット版を生成し、変更ファイル（+新規アセット実体）をユーザーへ渡す。
   `public_html` 直下を上書き → サーバーキャッシュクリア → スーパーリロード。
